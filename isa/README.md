# ISA 실무 Q&A 문제은행

대한민국 ISA(개인종합자산관리계좌) 제도에 대한 실무 Q&A 문제은행이다.
**LLM 학습 / RAG 구축 / FAQ Agent 평가**용으로 설계되었으며, 두 개의 지시문
(생성 Master Prompt, QA Audit Prompt)에 따라 **생성(Generator) → 검증(Validator)
→ 수정(Corrector)** 파이프라인으로 구축한다.

> ⚠️ **면책**: 본 문제은행은 현행 시행 법령을 근거로 작성했으나 자동 생성물이며,
> 세무·법률 자문이 아니다. 실제 적용 전 반드시 원문 법령(국가법령정보센터)과
> 소관기관(국세청·금융위)의 최신 유권해석으로 확인해야 한다. 특히
> `verification_needed=true`로 표시된 문항은 조문 번호·세부 수치 확정이 필요하다.

### 현행 ISA 핵심 파라미터 (Batch 01 기준)

- 연 납입한도 **2,000만원** / 총 납입한도 **1억원**(미납입분 이월 가능)
- 최소 의무가입(계약)기간 **3년** (3년 내 해지 시 감면세액 추징, 부득이한 사유 제외)
- 비과세 한도 **일반형 200만원 / 서민형·농어민형 400만원**
- 초과분 **9%(소득세) + 0.9%(지방소득세) = 9.9%** 저율 분리과세, 종합과세 배제
- 서민형 요건: 직전 과세기간 총급여 5,000만원 이하 또는 종합소득금액 3,800만원 이하
- 만기자금 연금계좌 전환 시 전환액의 10%(최대 300만원) 추가 세액공제

> **미시행 개편안은 본 문제은행에서 제외한다**(Master Prompt: 개정 예정 법안 제외).
> 2026년 7월 현재 미입법 상태인 항목은 다음과 같다.
>
> - **현행 ISA 한도 확대안**(연 4,000만원·총 2억원, 비과세 일반형 500만원·서민형 1,000만원)과
>   **국내투자형 ISA 신설안** — 2024년 정부 세법개정안에 포함됐으나 국회 심사에서
>   개정세법에 반영되지 않았고, 이후 조특법 개정안으로 재발의되어 계류 중이다.
> - **생산적 금융 ISA(청년형 ISA·국민성장 ISA)** — 2026년 경제성장전략에서 신설 방향이
>   발표된 현행 추진안. 재정경제부는 2026.3.3. 설명자료에서 구체적 방안이 정해진 바 없다고
>   밝혔고, 세부 수치·시행령은 미확정이다.
>
> ⚠️ **재검증 트리거**: 위 항목은 **2026년 7월 세제개편안 및 국회 입법 절차 완료 시점**에
> 확정된다. 확정 시 본 문제은행의 다수 문항(비과세 한도·납입한도·계산형 전부)의 정답이
> 바뀌므로, 발표 직후 **Batch 01~10 전체를 Validator에 재투입**해야 한다.

### 식별된 커버리지 공백 및 처리 현황

> **국내상장주식 '손실'의 손익통산 처리** (Batch 01 감사에서 식별) — **Batch 04에서
> 보강 완료**(`ISA-B04-001` 계산형, `ISA-B04-023` 세제). 다만 국내주식 손실을 과세소득과
> 통산할 수 있는지는 결론이 갈리는 쟁점이라, **조건부 정답(해석 A/B 병기)**으로 출제하고
> `verification_needed=true`로 원문 확정을 유보했다.
>
> - 해석 A(손실도 통산 제외) vs 해석 B(순손실 반영) — 예시에서 세액이 247,500원↔0원으로 갈림.
> - 확정 근거: 금융투자협회 손익통산 실무지침(*동일 종류 금융상품 → 배당 → 이자* 순),
>   국세청 유권해석 원문. **확정 시 단일 규칙으로 정정**한다.
>
> **후속 잔여 공백**: 증여/상속 시 세액 계산형(Batch 06 권장), 건강보험료·거주자판정 등
> 인접 제도 연계 문항 확대 권장.

## 사용법

### 1) 데이터 로드 (Python)

```python
import json
with open("isa/isa_qa_batch01.jsonl", encoding="utf-8") as f:
    items = [json.loads(line) for line in f if line.strip()]
print(len(items), items[0]["id"])
```

### 2) 기계 검증 실행

```bash
cd isa
python3 audit/validate.py isa_qa_batch01.jsonl
# 종료코드 0 = PASS(에러 없음), 1 = FAIL
```

### 3) RAG / 파인튜닝 활용 팁

- **RAG 청크**: 문항 1개(JSON 객체)를 1 청크로 사용. `question`+`answer`+
  `explanation`을 본문으로, `keywords`/`category`/`subcategory`를 메타데이터로 인덱싱.
- **FAQ Agent 평가**: `question`을 입력, `answer`를 정답 레퍼런스로 사용.
  `verification_needed=true` 문항은 평가셋에서 제외하거나 별도 표기 권장.
- **파인튜닝**: `question`→`answer`(+`explanation`) instruction 쌍으로 변환.

## 근거·검증 원칙

1. 현행 시행 법령만 인용, 개정 예정 법안 제외
2. 조문 번호·세부 수치 확신이 낮으면 값을 지어내지 않고 `verification_needed`로 표시
3. 모든 계산형은 단계별 계산식 + 검산 포함
4. 법률 사항과 증권사 운영 실무를 구분(운영 실무는 `basis_priority=10`)
5. 조건부 정답 문항은 조건별 결론을 함께 제시
